# ChIPseqSpikeInFree - Pipeline Skill

## Overview

Provide executable R/package-maintenance guidance for `ChIPseqSpikeInFree`, a spike-in-free ChIP-seq normalization package. Use this skill to help agents run the package workflow, maintain the repository, validate changes, and explain scaling-factor outputs.

## Usage

- Run the complete `ChIPseqSpikeInFree()` pipeline from BAM files and metadata.
- Prepare or validate metadata, chromosome-size files, and package inputs.
- Use individual functions: `GenerateBins`, `CountRawReads`, `ReadMeta`, `ParseReadCounts`, `CalculateSF`, `PlotDistr`, and `BoxplotSF`.
- Review, patch, test, or release the package without changing public APIs unnecessarily.
- Interpret `*_SF.txt`, QC status, turn points, and scaling factors.

## Response Format

- Lead with the command, code, or decision the user needs.
- For package-use questions, structure answers as: required inputs -> R command -> expected outputs -> interpretation notes.
- For maintenance questions, structure answers as: changed files -> validation command -> result/risk.
- Keep examples runnable and concise. Prefer one complete example over many alternatives.
- Call out batch-comparability limits: scaling factors are comparable only within the same jointly processed run and antibody context.

## Core Workflow

Use the pipeline in this order:

1. `ReadMeta()` validates sample metadata with required `ID`, `ANTIBODY`, and `GROUP` columns.
2. `CountRawReads()` counts BAM reads in genome-wide bins generated by `GenerateBins()`.
3. `ParseReadCounts()` converts raw counts into cumulative CPMW distributions.
4. `CalculateSF()` computes QC status, turn points, slopes, and scaling factors by antibody.
5. `PlotDistr()` and `BoxplotSF()` write distribution and scaling-factor summary outputs.
6. `ChIPseqSpikeInFree()` wraps the full workflow and invisibly returns the scaling-factor metadata table.

## Input Requirements

### Metadata

Metadata must be tab-delimited with a header:

```text
ID    ANTIBODY    GROUP
sample1.bam    H3K27me3    WT
sample2.bam    H3K27me3    K27M
```

Rules:

- `ID` must match BAM basenames or count matrix column names.
- Duplicate `ID` values are invalid.
- `COLOR` is optional and used for plots.
- Include samples from the same comparison batch together; do not calculate separate batches and compare their scaling factors directly.

### BAM And Genome Inputs

- Use BAM files aligned to the same genome represented by `chromFile`.
- Bundled `chromFile` aliases are `hg19`, `hg38`, `mm9`, and `mm10`.
- Custom chromosome-size files should be tab-delimited: chromosome name, size.
- Recommended `binSize` range is 200-10000 bp.
- `overlap` must be non-negative and smaller than `binSize`.

## Function Reference

Function | Purpose | Main Output
--- | --- | ---
`GenerateBins(chromFile, binSize, overlap, withChr, minChrSize)` | Create genome-wide bins | Data frame of `chr`, `start`, `end`
`CountRawReads(bamFiles, chromFile, prefix, singleEnd, binSize)` | Count reads per bin | `<prefix>_rawCounts.txt`
`ReadMeta(metaFile)` | Read and validate metadata | Metadata data frame
`ParseReadCounts(data, metaFile, by, prefix, binSize, ncores)` | Parse cumulative CPMW distributions | `<prefix>_parsedMatrix.txt`
`CalculateSF(data, metaFile, minFirstTurn, maxLastTurn, cutoff_QC)` | Calculate QC and scaling factors | Metadata with `QC`, `TURNS`, `SF`
`PlotDistr(data, SF, prefix, xlimMaxCPMW)` | Plot cumulative distributions and write SF table | `<prefix>_distribution.pdf`, `<prefix>_SF.txt`
`BoxplotSF(input, prefix)` | Plot scaling-factor summaries | `<prefix>_boxplot.pdf`
`ChIPseqSpikeInFree(...)` | Run the full workflow | All standard outputs plus invisible `SF`

## Complete R Example

```r
library(ChIPseqSpikeInFree)

metaFile <- "sample_meta.txt"
bams <- c("WT-H3K27me3.rmdupq1.bam", "K27M-H3K27me3.rmdupq1.bam")

sf <- ChIPseqSpikeInFree(
  bamFiles = bams,
  chromFile = "hg19",
  metaFile = metaFile,
  prefix = "test",
  binSize = 1000,
  singleEnd = TRUE,
  cutoff_QC = 1.2,
  maxLastTurn = 0.99
)
```

Expected files for `prefix = "test"`:

- `test_rawCounts.txt`
- `test_parsedMatrix.txt`
- `test_SF.txt`
- `test_distribution.pdf`
- `test_boxplot.pdf`

## Interpretation

- `QC = pass` means the sample is eligible for scaling-factor interpretation.
- `QC = fail: complete loss, input or poor enrichment` means `SF` is set to `NA`.
- `SF` is calculated within each antibody group.
- Larger `SF` indicates lower global histone mark signal relative to the run-specific reference sample.
- `TURNS` stores first and last turn-point coordinates used for slope-based SF calculation: `xMin,yMin,xMax,yMax`.
- Do not compare scaling factors from independent runs or batches unless all relevant samples were processed together.
